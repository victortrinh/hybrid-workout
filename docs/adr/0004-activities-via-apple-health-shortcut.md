# Activities arrive through an iOS Shortcut, not Strava

The plan was to import Apple Watch workouts from Strava: OAuth from Settings, a webhook on every new activity, laps from Strava's API. Strava now asks for a paid subscription to use its API, which is a yearly fee to read the athlete's own workouts. Instead, a second personal iOS Shortcut reads the workout from Apple Health when it ends and POSTs it to `/api/activities`, carrying the same Cloudflare Access service token as the Recovery Shortcut (ADR-0001, ADR-0003). There's no OAuth, no webhook, no token refresh, and no third party.

What this gives up: Shortcuts can't read a workout's laps, so Activities have none, and heart rate is the average and maximum of the Health heart-rate samples between the workout's start and end, which the server works out from the raw samples. Whether a run was on a treadmill is sent when the Shortcut can tell; otherwise the app uses the treadmill months in Settings. The Coach's matching (by date and Session type, asking "Which Session was this?" when ambiguous) doesn't depend on where Activities come from, so another source can replace the Shortcut later without changing it.
