# QA mocks: MSW over the real Hono app, on SQLite in the browser

Branch previews and `npm run dev:mock` run without any database so they can be used for QA: Mock Service Worker intercepts `/api/*` in the browser and hands each request to the Worker's own Hono app, whose `DB` binding is a small D1-shaped adapter over sql.js (SQLite in WebAssembly) with `migrations/*.sql` applied on start. Named scenarios fill that database, pin the date the app thinks it is, and set device settings, so any state of the Program (before Week 1, a Deload week, Race week, a carried Key session) is one URL away. Production, `npm run dev`, `npm run preview` and the end-to-end tests keep the real Worker and D1; mock code only reaches a bundle built with `VITE_API=mock`, and CI fails a production build that contains it.

We first leaned towards seeding the real local D1 with scenarios instead, since `npm run dev` already runs the real Worker. That doesn't work on a branch preview without a database, and the shared `compromised-preview` D1 leaks state between branches and needs migrating by hand. Handwritten MSW handlers were the other option; they would have to repeat the sync rules (a later edit wins) for every new table, and a forgotten one would make previews quietly show wrong data. Running the real Hono app keeps the mocks free of logic of their own: a new migration or route works in mock mode without touching them.

What this gives up: a page has one service worker, so mock builds don't register `/sw.js` and offline behaviour can't be QA'd on a preview (`e2e/offline.e2e.ts` still covers it against the real build). Mock builds carry about 1 MB of WebAssembly. Previews no longer exercise D1 itself or Cloudflare Access's signed assertion; the end-to-end tests and production do. The Shortcut routes are reached in mock mode with the service token's two headers, which the Worker already accepts when Access isn't in front (`src/worker/access.ts`).
