# Lock-screen cues: Web Push from a Durable Object timer, in a Worker of its own

iOS freezes a web page once it's off screen, so a Live session's buzz and beep at each Block change, and at the end of a rest, stop while the athlete is in their music app or has the phone locked. The clock itself loses nothing: it's timestamps, and it catches up on return. To get the cue out on time, the page hands the server the list of cues ahead when it goes off screen: every timed Block's end until the clock next waits on a tap (the Ready screen, a Block run to a distance, a checklist), or the end of a rest. A Durable Object keeps the list and sets an alarm on the next cue. When the alarm fires it sends a Web Push notification, which iOS shows on the lock screen or over any app, with the system sound and a buzz, without stopping the music. When the app comes back on screen, the page takes the list back, so the on-screen cues and the pushes never both go off. The page works the list out with the same `advance` the clock runs on (`src/app/lockScreenCues.ts`). The server knows nothing about Sessions; it only keeps time.

Push is sent with WebCrypto alone (RFC 8291 aes128gcm encryption, RFC 8292 VAPID), no library (`src/cues/push.ts`). The timer is a Worker of its own, `compromised-cues` (`wrangler.cues.jsonc`), which the app's Worker reaches through a `CUES` binding. Cloudflare makes no preview URLs for a Worker that implements a Durable Object, and the branch previews are how changes get QA'd (ADR-0005). The timer deploys on its own (`npm run deploy:cues`), and rarely changes.

We also considered rendering the cues into one audio track and playing it like a podcast, which iOS keeps playing in the background. By default that stops Spotify or Apple Music, and whether Safari's "ambient" audio session mixes with them in the background is unproven. A Cron Trigger only fires once a minute at best. Queues can't cancel a delayed message, so every pause would leave stale cues to filter out.

What this gives up: iOS only allows Web Push for an app added to the Home Screen, on iOS 16.4 or later, and notifications must be allowed once. A push can land a second or two late. If the page can't reach the server as it hides (no signal), there are no cues that time, and the clock on screen is still right when the app comes back. Turning lock-screen cues on is per phone, and the server keeps one subscription: the last phone to turn it on.
